The player enters a tile (initializing the game loop, the player spawns on the start tile; thereafter, the start tile is never used again; this is the only difference from the start). 
1) The tile is marked as "ACTIVE". 
2) The tile that they previously came from is marked "PREVIOUS". 
3) the game checks to see where the active tile's exits are. 
4) At every exit, a "CONNECTING" tile is considered for spawning. (The exception is the tile that is connected to entrance that the player came through, which is connected to the previous tile - this tile is skipped). 

5) First, the program checks to see the world location (the code may suggest that the world is a 10x10 grid, I've decided to change it to a 7x7 grid - so the grit should cover a square area with corners at (3,3) and (-3,-3).) 
5a) If there is a "PERMENANT" tile that has been laid down in a previous run that should be at that location, it is the tile that is connected. (If the world position is outside of the 7x7 grid, the program needs to wrap back around to the other extreme - so instead of checking for a tile at (4,3), the program checks if there is a tile at -3,3, and if there is, uses that - and subsequent movements into the positive x continue to follow this).  
5b) If there is no permanent tile there, a tile is randomly selected from all available tiles (located in the res:\scenes\tiles folder). 
6) In either case, the tile is spawned there (offset 20 units from the center of the active tile). 
7) The connecting tile is then assessed for number of doors available. 
8) The tile is rotated so that one of the available doors on the connecting tile lines up with the door on the active tile that it was spawned near. 
9) Once positioned, all avaiable item drop points (available in the Maze/ItemSpawn node) on the connecting tile are placed in an array and randomly sorted.
10)  The tile's position is checked to whether the player died on that tile during a previous run, and whether that previous run's inventory is still available.  
10a) If both conditions are met, then a backpack containing that inventory is dropped at the first item drop point and the item placement loop breaks. 
10b) If the loop continues, available items are randomly sorted (only the 5 currently lowest numbered notes are available, plus all other objects that have not been picked up yet). Each drop point has a 3% base chance of having an item present at any given drop point. However, once one object has dropped on this tile, the loop breaks.
11)  All available entity postions (Maze/EntitySpawn) on the connecting tile are placed in an array and randomly sorted.
12)  If a previous player's inventory was dropped here, an 'Effigy' is spawned at the first entity point and the entity placement loop breaks. Else, each spawn point has a 4% chance of spawning an entity. The type of entity changes based on Sanity - Stalkers have a base 90% chance of spawning - current sanity level (sanity goes up to 100, so when the game first starts, and sanity is high (greater than 90%), there is no chance of a stalker spawning - negative percentages counts as no spawn chance). If a Stalker is not spawned, then an Effigy spawns. Once one entity has spawned, the entity loop breaks.
13)  Once all tiles for any avialable door is placed for the active tile, the previous tile's connecting tiles are 'cleaned up'. If there are any entites or unpicked up items on these tiles, they are also cleaned up. The only tiles remaining in the world should be the Active tile, the Previous tile, and between 0 and 3 connecting tiles.
14)  All entrance/exit markers on the active tile are 'inactivated', as they will no longer be used while the player is on this tile. The previous tile's entrance/exit markers are reactivated.
15)  If, while the player is on the active tile, they pick up an item, the item is added to the player's inventory and removed from the array of items that can be dropped. If they pick up the inventory of a previous run, those items (and those items only - there may be other inventory drops that still exist out there). 
16)  If the player dies on the active tile, then the location on the world map is logged, along with the inventory (which is then added to the dropped inventory list), type of death (sanity loss [fragmentation], stalker death [consumed], the run was prematurely terminated [harvested], etc - these are the only three I can think of off the top of my head). Permenant tile locations are checked to see if they have moved (50% chance to stay in place, even chance to move 1 tile over in x, y, -x, or -y) and their locations are saved for the next run. The player is then sent to the death screen.
